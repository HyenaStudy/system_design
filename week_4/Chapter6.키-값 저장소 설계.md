키-값 저장소 설계

키-값 저장소 : 키-값 데이터 베이스라고도 불리는 비 관계형 데이터베이스 이다

**단일 서버 키-값 저장소**

- 한 대 서버만 사용하는 키-값 저장소를 설계하는 것은 쉽다.
- 단점: 모든 데이터를 메모리 안에 두는 것이 불가능하다는 단점이 있다
    - 데이터 압축
    - 자주 쓰이는 데이터만 메모리에 두고 나머지는 디스크에 저장

**분산 키-값 저장소**

- 키와 값 형태로 데이터를 저장하는 분산 시스템
- 여러 노드에 데이터를 분산 저장해 확장성과 장애 대응성을 확보
- 주로 캐시, 세션 저장소 간단한 상태 관리에 사용
- CAP정리
    - 데이터 일관성
        - 모든 노드가 항상 동일한 데이터를 반환
        - 시간이 지나면 모든 노드가 동일한 상태로 수렴
        - Quorom 기반 읽기 쓰기
        - N, R, W설정으로 일관성과 가용성 트레이드 오프조절
    - 가용성
    - 네트워크 분할 허용
        - 네트워크 분할이 발생하면 C와 A중 하나로 선택해야함
        - 현실적인 분산 시스템은 대부분 P를 전제로 설계

**실세계의 분산 시스템**

- 분산 시스템은 파티션 문제를 피할 수 없음
- 파티션 문제가 발생하면 우리는 일관성과 가용성 사이에서 하나를 선택해야한다
- 분산 시스템의 목적에 맞게 CAP정리를 적용해서 설계해야한다

**Redis Vs DynamoDB**

Redis

- 인메모리 기반 키-값 저장소
- 매우 빠른 응답 속도 (ms 이하)
- 캐시, 세션, 실시간 데이터 처리에 최적화
- 디스크는 보조 수단 (RDB, AOF)
- CAP
    - 기본 성향: CP 또는 AP (구성에 따라 달라짐)
    - Redis Cluster
        - 네트워크 분할 시 일부 노드 차단 → Consistency 우선
    - Redis Sentinel
        - 장애 감지 후 리더 선출
        - 장애 순간에는 일시적 가용성 저하 발생 가능
- 데이터 일관성
    - 단일 노드 또는 리더 기준 읽기
    - Replica 읽기 사용 시 최신 데이터 보장되지 않을 수 있음
    - 트랜잭션으로 원자성 보장 가능

DynamoDB

- AWS 완전 관리형 NoSQL 키-값 / 문서 DB
- 디스크 기반 + 내부적으로 강력한 분산 구조
- 대규모 트래픽, 무한 확장에 초점
- 운영 부담 거의 없음
- CAP 관점
    - 기본 성향: AP
    - 네트워크 분할 상황에서도 서비스 지속
    - 일관성보다 가용성과 분할 허용을 우선
    - 분산 환경을 전제로 설계됨
- 데이터 일관성
    - 기본: Eventual Consistency
    - 옵션으로 Strong Consistency 제공
    - Read 요청 시 ConsistentRead = true
    - 리전 내에서만 강한 일관성 보장
    - 일관성 선택이 비용과 성능에 직접 영향

### 시스템 컴포넌트

- 키-값 저장소 구현을 위한 핵심 기술
- Dynamo, Cassandra, BigTable

### 데이터 파티션

- 대규모 데이터를 여러 서버에 분할 저장
- 고려 사항
    - 데이터를 여러 서버에 고르게 분산 가능한가?
    - 노드 추가/삭제 시 데이터 이동을 최소화할 수 있는가?
- 해결책: 안정 해시
    - **동작 원리**
        - 서버와 키를 동일한 **해시 링** 위에 배치
        - 키 위치에서 시계 방향으로 순회 증 첫 번째 만나는 서버에 저장
    - **장점**
        - **규모 확장 자동화** : 시스템 부하에 따라 서버 자동 추가/삭제 용이
        - **다양성** : 가상 노드수 조정 → 고성능 서버에 더 많은 부하 할당 가능

### 데이터 다중화

- 높은 가용성(Availability)과 안정성 확보
- 동작 방식
    - 데이터를 **N개** 서버에 비동기적으로 복제
    - 해시 링에서 키 위치로부터 시계 방향으로 만나는 **최초 N개 서버** 선정
- 주의 사항
    - 가상 노드 사용 시 실제 물리 서버가 중복 선택되지 않도록 처리
    - 데이터 센터 장애 대비 ,사본을 다른 센터에 보관 및 고속 네트워크 연결

### 데이터 일관성 (Data Consistency)

- Quorum Consensus (정족수 합의)
    - 다중화된 데이터 간의 동기화 및 일관성 보장
- 주요 개념
    - **N**: 사본 개수
    - **W**: 쓰기 정족수 최소 W개 서버에서 쓰기 성공 시 성공 간주
    - **R**: 읽기 정족수 최소 R개 서버에서 응답 수신 시 성공 간주
