# 안정 해시 설계

## 1. 문제 상황 확인
1. N개의 캐시 서버가 존재한다.
2. 해당 서버들에게 부하를 균등히 분배하기 위해 해시가 적용된다.
3. 정책(해시 전략)이 변경돼도 분산의 균등 정도는 최대한 지켜야 한다.

## 2. 문제 분석
### (1) 기존 해시의 문제점: 재배치 이슈
- 가장 간단한 해시 전략인 모듈러 연산은 `bucket = H(key) % N` 형태를 가짐
- 여기서 `N`이 증감되면 모든 `H(key)`에 대해서 `bucket`의 값이 전부 바뀜
- 변동된 값이 부하의 분산도를 유지한다는 보장이 없어서 모든 `bucket`이 흔들림
- 해시 함수의 치역 범위 변동을 감당하기 위해 함수 정의를 바꾸는데, 매핑 정보를 보존할 방법이 없음

### (2) 재배치 최소화 방안 고민
- 재배치는 필연적이므로 영향을 최소화할 것
- 기존 모듈러 해시는 버킷 슬롯을 중심으로 매핑 정보를 전달
  - 그래프 설계에서 간선을 중심으로 이중 리스트를 활용하는 것처럼
  - 정점이 증감되면 이중 리스트 전체 길이가 바뀌게 됨
- 슬롯 중심이 아닌, 노드(서버) 중심으로 매핑 정보를 전달해보기
  - 그래프 설계에서 정점을 중심으로 다중 맵을 활용하는 것처럼
  - 정점이 증감되면 간선만 고려해서 갱신 값만 추가하면 됨
- 위 방식을 기반으로 설계한 해시의 예시가 **안정 해시**

## 3. 안정 해시 설계
### (1) 내 나름대로 이해한 안정 해시 매커니즘
0. 일련의 해시 공간을 구부려 해시 링을 만든다
1. 노드(요청이나 데이터가 매핑으로 도달하는 목적지)의 수치 정보를 사전 배치한다
2. 요청 데이터가 들어오면 해싱돼서 수치화되고 이를 해시 링에 올린다
3. 해당 요청 데이터가 매핑되는 노드는, 요청 데이터 수치에서 시계 방향으로 돌렸을 때 가장 가까운 노드다
4. 이로써 노드 개수가 증감돼도 특정 데이터만 재배치되면 되므로 전체 슬롯의 흔들림을 줄인다

### (2) 안정 해시에 대한 고찰
**해시는 무조건 일대일함수가 아니다. 오히려 짝수 다항함수로 바라봐야 함**

- 내가 착각하는 일대일 대응 해시는 암호학에서나 볼법한 거(perfect hash)
- 시스템 설계의 해시 함수는 부하 분산(최대한 같은 치역에게 매핑)이 1차 목표
- 여기서 부하 집중을 막기 위해 균등분산(치역 당 정의역 개수 비율이 비슷)이 2차 목표

**어떻게 요청 데이터가 가장 가까운 노드를 찾을까**

- 놀랍게도 **이진 탐색**이라네요
- 해시 링 자체가 사전정렬된 해시 공간을 구부린 것
- 그래서 요청 데이터 해싱값을 시작으로 이진 탐색해서 가장 근접한 노드를 찾음
- 만약 **요청 데이터가 90이고 가장 가까운 노드가 10이면, 이진 탐색해서 나온 결과가 `null` → 그럼 노드들 중 최솟값을 선택 매핑**

**자바에서 직접 구현한다면?**

- 해시 링 구조 설계는 **`TreeMap`**이 가장 적합
- `TreeMap` 자료구조가 균형 이진 탐색 트리(레드블랙 트리)
- 레드블랙 트리는 BST의 편중을 방지하고 강제 균형(높이를 logN에 가깝게) 만드는 자료구조
  - 모든 노드는 Red 또는 Black
  - 루트는 항상 Black
  - 모든 리프(Null 노드)는 Black
  - Red 노드는 Red 자식을 가질 수 없음 (Red는 연속 금지)
  - 어떤 노드에서 리프까지 가는 모든 경로의 “Black 노드 수”는 동일
  - 삽입은 기존 BST처럼, 삽입할 때는 Red
  - Red 노드의 부모가 Red이면 규칙 위반 → 회전(부모-자식 위치변환) 혹은 색변환

## 4. 안정 해시 보완

### (1) 기존 안정 해시의 문제점 - 파티션 불공정
- 파티션은 노드와 노드 간 공간을 생각하면 됨
- 즉 큰 노드의 정의역 범위라고 생각하기
- 근데 이 정의역 범위가 노드 가감으로 인해 파티션 너비가 엉망진창
- 파티션 너비가 넓을수록 특정 노드에 부하가 집중될 위험 존재

### (2) 파티션 불공정을 극복하기 위한 가상 노드(vnode)
- 가상 노드는 실제 노드를 가리키는 나들목이라 생각하자
- 이 가상 노드는 해시 링 위에 무작위로 배치됨
- 요청 데이터의 해싱값은 가장 가까운 노드를 목적지 삼는 건 동일
  - 마주친 게 실제 노드다? 그럼 그대로 매핑
  - 마주친 게 가상 노드다? 그럼 그 가상 노드가 가리키는 실제 노드로 매핑
- 가상 노드 구현은... 그냥 노드 인터페이스를 구현해서 실제 노드 정보를 필드로 갖게하면 될듯?
