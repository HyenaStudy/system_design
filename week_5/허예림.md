### 일관성 모델

- 키-값 저장소를 설계할 때 고려해야할 중요한 요소
    - 강한 일관성 : 모든 읽기 연산은 가장 최근에 갱신된 결과를 반환한다
        - 쓰기 연산이 반영될 때 까지 해당 데이터에 대한 읽기/쓰기를 금지
    - 약한 일관성 : 읽기 연산은 가장 최근에 갱신된 결과를 반환하지 못할 수 있다
    - 최종 일관성 : 약한 일관성의 한 형태로 갱신 결과고 결국에는 모든 사본에 반영되는 모델이다

**비 일관성 해소 기법 1 : 데이터 버저닝**

- 분산 시스템에서 데이터 일관성 유지를 위해 데이터를 덮어 쓰지 않고 모든 버전을 남겨서 기록

## 장애 처리

### 1. 장애 감지

**멀티 캐스팅**

- 시스템에 있는 모든 노드는 약속된 특정 멀티캐스트 ip 주소와 포트를 리스닝 상태로 열어둠 (멀티 캐스팅 채널 구성)
- 주기적으로 멀티 캐스트 주소로 자신의 상태 정보를 담은 패킷 전달
- 특정 서버로 부터 정해진 시간동안 수신이 오지 않으면 해당 서버를 장애 상애라고 판단

**유니 캐스팅**

- 시스템 내 모든 서버는 클러스터에 참여하고 있는 다른 모든 서버의 IP 주소 목록을 가지고 있음
- 서버 A는 자신이 가지고 있는 서버 주소 목록을 순회하면서 생존 사실 전파
- 지정된 시간 내 특정서버로 부터 패킷이 오지 않음면 장애로 판단

### 2. 일시적 장애 처리

**엄격한 정족수**

- 담당 노드 중에서 2개가 OK한 경우에만 성공 판단
- 담당 노드 3개중 2개가 죽었을 경우 쓰기를 실패함

**느슨한 정족수**

- 담당 노드가 아닌 현재 살아있는 노드 아무 노드 2개 이상이 ok이면 성공으로 판단
- 담당 노드가 죽어도 대타 노드에게 데이터를 맡김
- 원래 A노드에 저장되야함 → A 응답 없음 → 임시로 D로 대체 → 임시로 맡았다는 정보와 함께 로컬디스크의 별도 공간에 기록 → A가 복구 된경우 돌려줌 (주기적으로 A 상태 체크)

**동기식 복제 (Multi-AZ)**

- 개발자가 주 DB에 데이터를 씀 → 주 DB는 물리적으로 떨어진 다른 DB에도 똑같이 쓰기 연산 수행
- 모든 다른 DB의 쓰기가 완료되었을 경우에만 성공 연산을 보냄

**읽기 전용 복제본 (Read Replica) / 비동기식 복제**

- 주 DB에 데이터를 씀 → 주 DB는 쓰기만 수행
- 쓰기를 수행하지 않을 때 다른 복제 DB들에게 데이터를 던져준다

### 3. 영구 장애 처리

- 반-엔트로피 프로토콜 : 사본들을 비교하여 가장 최신 버전으로 갱신하는 과정
- 머클 트리 : 데이터를 전체 비교하지 않고 데이터의 해시값만 계층적으로 비교함

### 4. 쓰기 경로

카산드라 같은 LSM 트리 기반 데이터 베이스 기준

- 커밋 로그에 들어온 데이터 기록
    - 아직 메모리에만 데이터가 있는데 갑자기 서버 전원이 꺼지면 데이터가 날라가게 됨으로 방지하기 위한 복구용 백업
- 멤테이블에 기록 (메모리 기록)
    - 데이터를 메모리 구조에 맞게 저장
- 클라이언트에 성공 응답
- 쓰기 요청이 계속 들어와서 메모리의 멤 테이블이 가득 찬 경우 디스크(SSTable)로 이동 및 멤테이블과 커밋로그 삭제

### 5. 읽기 경로

- 멤 테이블(메모리) 확인 → 디스크에 Flush되기 전이라면 여기서 바로 리턴
- 없다면 디스크를 뒤져야하는데 디스크는 느리기 때문에 블룸 필터에 조회
    - 블룸 필터 : 없는 데이터를 찾느라 불필요하게 무거운 디스크를 읽는 것 방지
    - 블룸필터는 거짓 양성을 뱉을 수 있음
    - 고정된 크기의 비트 배열과 여러개의 해시 함수를 통해 데이터의 존재 여부 판단
    - 입력값을 넣으면 배열의 인덱스 0~9를 반환하는 함수 여러개 준비
    - 해싱 후 나온 값의 인덱스를 1로 변경
- 디스크 탐색
    - 데이터가 여러번 수정되었을 경우 여러 SSTable에 값이 흩어져 있을 수 있음
    - 관련된 데이터를 가진 모든 파일을 가져옴
    - 타임스탬프가 가장 최신인 데이터만 인정하고 나머지 버림
